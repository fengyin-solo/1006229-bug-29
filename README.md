# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 技术供水 / 拦污栅的口径约定（v2）

页面统一由 `components/ModulePage.vue` 渲染，所有业务判断集中在
`api/local-service.ts`；数据带版本壳（`data/local-store.ts`），老版本打开自动迁移
（`data/migrate.ts`）。

### 异常与停运

- **异常量 = 状态属于「异常态」的记录数**（各模块异常态在 `modules.ts` 的
  `abnormalStatuses` 中登记）。列表状态图例、页面卡片、运营概览、导出汇总行全部由
  `local-service.ts` 现算，不再各算各的。
- **「已停运」是终态，单独统计，不计异常**。停运即清除异常标记，停运记录仍保留在列表里
  可查；复运时把异常标记、停运标记、滤水器压差（重新现场取数）一起回到正常口径。
- 同一系统重复复运：幂等键 `cooling-resume:<系统编号>`，指标只回落一次、联动清污任务只
  生成一笔。

### 取数失败 vs 数据本身为空

`data/measure.ts` 模拟现场表计（换后端时换成实测接口）：

- **取数失败**（通信超时等可重试故障）：读数留空显示「暂无」，写明失败原因，行内给
  「重试取数」入口；提交检查不阻断，其余测点照常登记。
- **传感器故障等不可重试**：留空、说明原因、提示检修，不显示重试按钮。
- **实测本身为空**（如备用管路未投运无水流）：留空显示「暂无」，说明是现场空值而非取数
  失败，也不提供重试。

### 取值冲突：实测优先

现场实测值与限值冲突时，**一律以实测值为准登记**：限值只用于越限判定（越限则状态记异常
并在「取数说明」中写出实测值与限值），绝不用限值替换或改写实测值。列表、概览、导出、
联动台账读取的是同一份实测口径。

### 老数据迁移（v1 → v2）

- 老数据按原有编号保留；新种子里新增的记录（缺项）按编号补入，老记录编号不在种子中的
  原样追加。
- **早期「取不到数误记 0」识别规则**（在 `measure.ts` 的 `isLegacyFalseZero` 集中维护）：
  检查日期早于取数通道上线日 **2026-09-03**，且压力/流量/水温/压差被记成 `0` 或不可解析
  的占位文本，判定为取不到数时误记的 0。处理方式：**按检查日期从早到晚**逐测点重新取数
  回填；仍取不到的留空并写明原因。
- 异常/停运/待办标记统一按状态重算，修正了旧示例数据中「状态正常却挂异常标记、状态异常
  却没标记」的错位；数值字段（数量、压差、限值字段等）统一数值化。
- 技术供水缺「所属机组」的，按系统编号回填（COOL-0001…0004 → 1…4 号机组，其余归公用
  系统）。

### 值班清污台账与拦污栅联动

- `duty` 台账（事件流水）是**清污条数的唯一口径**：拦污栅行内「清污次数」在读取时投影
  （`projectRow`），导出清单、技术供水页脚、拦污栅值班面板都算自同一份流水。
- 技术供水「系统复运」按所属机组自动生成一笔清污任务（如 4 号机组 → TRAS-0004），在
  拦污栅台账「确认完成」后条数 +1；台账自身「安排清理 → 确认完成」同样入账。重复复运、
  重复安排、重复确认均幂等，只计一次。
- 清污完成后按现场实测压差登记，超过 0.30m 限值也按实测保留并据实登记栅体状态。

### 备品备件领用

同一备件在一个库存周期内重复提交领用只扣减一次数量（行内 `consumed` 幂等）；办理验收
补货后重置，允许下一周期再次领用；扣减后低于最低储备量自动转「待补充」。

### 验证

`npm run verify` 运行 `scripts/verify.mjs`：在 Node 中模拟 localStorage，覆盖迁移回填、
取数失败/空值/重试、实测优先越限、停运复运幂等、跨页清污条数一致性、列表/概览/导出
同口径、领用幂等等场景。
