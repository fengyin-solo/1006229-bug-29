# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` / `cooling-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 技术供水与拦污栅口径（v2）

所有读写落在同一个 localStorage 信封（行数据 + 量测读数 + 清污台账 + 动作令牌），
列表、概览、另存清单、值班清单都通过 `src/data/selectors.ts` 的派生选择器读同一份。

- **系统复运**：新增「系统复运」动作，把异常系统数（随状态）、停运标记、滤水器压差一次性回落到
  正常口径；状态守卫 + 落账令牌保证同一系统重复复运只回落一次。
- **取数三态**：`ok` 实测值 / `empty` 测点无数值（暂无）/ `failed` 取数失败。提交时若供水流量
  取数失败会明确报“取数失败”及原因且不落地；数据本身为空则留空显示“暂无”并说明。失败给单字段
  「重试取数」入口。
- **异常口径**：技术供水异常量按「异常」状态计，「已停运」单列；概览、列表、导出汇总一致。
- **早期误记 0 的识别规则**（见 `domain.ts:isSuspectLegacyZero`）：有量测限值的字段值为 0、
  检查日期早于 `2026-08-01`、且 0 与非停机状态并存，判为“取数失败误记 0”，迁移成取数失败、
  留空待重新取数；真实的 0（停运断水等）保留。
- **取值冲突规则**（由实现方定，见 `domain.ts`）：两边取值冲突时按
  在线实测 > 人工补录 > 台账迁移，同源再比采集时间；**实测与限值冲突时一律以实测为准**，
  限值只决定越限标记，不夹逼、不置零。依据写在每条读数的 `basis` 与页面 ⓘ 提示里。
- **清污台账联动**：拦污栅「确认完成」清污条数 +1 记进共享台账；重复提交（已是已清理）不重复加，
  同一栅重新安排后再确认算新一轮可再加。拦污栅页、技术供水页脚、值班清单读到同一总数。
- **老数据迁移**：旧的扁平存储按原编号合并，同编号保留改动、种子新增字段补齐、缺编号追加。
  逻辑校验脚本：`frontend/scripts/scenario-check.ts`。
